# 居宅から届く 提供票・別表 (FAX / 写真) の照合

居宅介護支援事業所から届く **サービス提供票 (第6表)** と **別表 (第7表)** を読み取り、
order-app の DB (ほのぼのと同期した新システム) と突き合わせて、食い違いを一覧にする。2026-11-13 作成。

> ★ PDF・画像・読み取り結果・正解データは **個人情報**。repo に入れない。出力 (`--out`) は既定で OS の一時フォルダ。

## 使い方

```bash
cd apps/order-app
# FAX のスキャン (PDF)
node scripts/teikyohyo-fax/run.mjs --pdf <FAX.pdf> --all
# スマホの写真 (何枚でも。提供票 → 別表 の順に並べる。別表は直前の提供票の人にひも付く)
node scripts/teikyohyo-fax/run.mjs --pdf 提供票.jpg --pdf 別表.jpg --all
```

| オプション | 意味 |
|---|---|
| `--out <dir>` | 出力先 (既定 `OS の一時フォルダ/teikyohyo-fax/<PDF名>`) |
| `--pages 1-10` | 一部のページだけ |
| `--snapshot <json>` | DB の控えを指定 (既定 `OS の一時フォルダ/teikyohyo-fax/snapshot.json`) |
| `--refresh-db` | DB の控えを取り直す (★ 全件読み。並行セッションに一報し、返事を待ってから) |

DB の控えは 12 時間以内のものがあれば使い回す (DB を読まない)。

| `--area <拠点>` / `--office-bn <番号>` | 照合する事業所 (ケアサポ / 誉田 / 高品 / 花見川 / 茂原。既定 ケアサポ) |

★ 事業所は `--area` / `--office-bn` で切り替える (`_office.mjs` → `migrations/_fukuyogu_office.mjs` の 5 事業所)。
run.mjs が 2 段目・控え・照合に同じ引数を渡す。既定 (引数なし) はケアサポで、判定・出力は切り替えを入れる前と同じ。
- 控えは事業所ごとに別ファイル (`snapshot.json` = ケアサポ / `snapshot_<拠点>.json`)。控えには取った事業所が記録され、
  match.mjs は 照合の事業所と違う控えを渡されると止める (記録の無い古い控えは ケアサポのものとして扱う)。
- 番号が読めないときの予備の事業所名の判定は `_office.mjs` の `NAME_RE` (誉田 = Hana/ハナ+ムツミ、高品 = ムツミ福祉用具+高品 …)。

## 流れ

| 段 | script | 中身 | DB / API |
|---|---|---|---|
| 1 段目 | `run.mjs` + `prep.py` | ページの分類 (提供票 / 別表 / 実績表 = 裏紙 / 白紙 / 不明)・向き・傾き・罫線からセル・番号欄を 1 桁ずつ (伏字 ● の判定) | どちらも使わない (tesseract.js) |
| 2 段目 | `claude.mjs` | 提供票・別表だけを Claude で読む (白紙・裏紙は送らない)。まず claude-haiku-5-5、検査に掛かったら claude-sonnet-5-5 | Anthropic API |
| 控え | `snapshot.mjs` | 利用者・認定・割当・発注・明細・用具・負担割合証を 1 回だけ読む (READ ONLY・直列・5xx/HTML で止めてリトライしない) | Supabase (12 時間使い回し) |
| 照合 | `match.mjs` | 利用者の特定 (3 段階) と項目の比較 → `match_result.json` / `.csv` / `.html` | 控えだけ |
| 精度 | `eval.mjs` | 正解データ (`--gt`) と比べる (開発用) | 控えだけ |

### 2 段目で Sonnet に読み直させる条件 (claude.mjs `problems`)

- 提供票: 被保険者番号が 10 桁 (英字 H・伏字 ● を含んでよい) でない / 保険者番号が 6 桁でない・**検証数字が合わない** / 氏名なし / 居宅名なし /
  生年月日が提供月の時点で 40〜110 歳の外 (元号の取り違え 昭和↔平成 を弾く。`CONST_AGE`)
- 別表: ケアサポの行で 単位数 × 回数 ≠ サービス単位 / 利用者負担 > 費用総額 / 費用総額 ≠ 請求額 + 利用者負担 (公費なし・±2 円)
- 最後まで年齢が合わない生年月日は使わない (`birth` = null、元の値は `birth_rejected`)

## 出力の見方 (match_result.csv / .html)

| 判定 | 意味 | すること |
|---|---|---|
| ✅ 確定 | 利用者が 1 人に決まった | 「食い違い」の列だけ見る |
| ⚠ 要確認 | 番号は合うが氏名が違う / 番号が読めず氏名だけで近い / 候補が近い / 伏字で絞り切れない / 生年月日が違う | 「理由」と候補を見て人が決める |
| ❌ 該当なし | 番号も氏名も閾値に届かない | うちの利用者ではない可能性 |
| － 対象外 | 別表にケアサポ (1272400050) の行が無い / 提供票にケアサポの行が無い | 宛先違いの可能性 |

### 閾値 (`match.mjs` の `TH`。出力の HTML にも載る)

| 名前 | 値 | 意味 |
|---|---|---|
| `nameSim` | 0.6 | 氏名 (見えている文字) の一致率の下限 |
| `margin` | 0.15 | 1 位と 2 位の総合点の差の下限 (これより近いと ⚠) |
| `minScore` | 0.55 | これ未満は ❌ |

総合点 = 番号 0.5 (伏字なら見えている桁の割合で割り引く) + 氏名 0.3 + 生年月日 0.15 + 性別 0.05 − 生年月日が違えば 0.2。
✅ にするのは 番号が一致し、さらに 氏名 か 生年月日 が一致するとき。**伏字のある番号は 番号だけでは ✅ にしない** (見えている桁 + 氏名 + 生年月日 がそろったとき)。

### 比べる項目 (確定した人だけ)

要介護度 / 居宅 / ケアマネ / 認定状態 (認定済・申請中) / 負担割合 (別表の給付率 と その月の 負担割合証 → 認定 → 利用者マスタ の順の給付率) /
用具・単位数 (別表のケアサポの行 と 貸与中の品目。回数 2 以上の行は台数に展開)。
読めなかった欄は「食い違い」ではなく「判定できない項目」に出す。

## 扱いの決まり

- **伏字「●」**: 個人情報保護で居宅が伏せた文字。読み取りでは推測で埋めず ● のまま返させる (プロンプトに明記)。照合では どの文字とも一致するワイルドカード。
  伏字入りの生年月日 (昭●年9月24日) は 見えている部分 (元号+年・月・日) のうち 2 つ以上が合えば一致。
- **委託**: 地域包括支援センターが居宅に委託している人は、提供票の居宅名が 包括 か 委託先 のどちらかになる。
  照合は「認定の担当居宅」か「担当ケアマネの所属居宅 (委託先)」のどちらかと合えば一致。
- **H 番号 (生保単独)**: 被保険者番号が H で始まる人。請求は 保険 0%・公費 100% だが、居宅のソフトは 給付率 90% + 公費 10% と印字することがある。
  負担割合は「利用者負担 0 円 なら一致」で判定する。番号の英字 H は落とさない (2 段目の検査も H を許す)。
- **ケアサポが出した実績報告の控え** (「サービス事業者 → 居宅介護支援事業者」の向き) が混ざることがある → 種類の判定で other にして照合しない。
- **裏紙**: ケアサポのサービス利用実績表 (縦向き) と白紙は 1 段目で外し、API に送らない。

## 費用と精度 (2026-11-13 時点)

- 費用: 1 ページ 約 $0.0018〜0.0025 (約 0.3 円)。Sonnet で読み直すと その 1 ページだけ 約 $0.02。
  R8-09 の FAX 40 ページ (送ったのは提供票・別表 21 ページ + 不明 1) で 約 6〜8 円。月 1,000 ページで 約 250〜400 円の見込み。
  `claude.json` の `summary` と ページごとの `cost` に トークン数と金額を残す。
- 精度 (正解データと比べたもの): R8-09 の FAX 40 ページ → 種類 40/40、利用者の特定 11/11 確定・**別人 0**、
  番号・要介護度・性別・生年月日・ケアマネ・単位数・給付率 100%、居宅 10/11 (FAX の「ケイ・ティ」→「ケイ・ケイ」はあいまい一致で吸収)。
  スマホ写真 (提供票 + 別表・伏字あり) 1 名 → ✅ 確定・項目すべて一致。
- 1 段目のローカル OCR は 分類・向き・白紙/裏紙の除外 に使う。文字 (氏名・番号) は 2 段目の Claude が主役。

## 設定

- API キー: `order-app/.env.local` の `ANTHROPIC_API_KEY` (値はログにも出力にも出さない)。
- DB: `kaigo-app/.env.local` の service_role で READ ONLY。
- Python: PyMuPDF / OpenCV / NumPy / Pillow。Node: tesseract.js / @anthropic-ai/sdk (order-app の devDependencies)。
- tesseract の学習データは初回に CDN から取り、`OS の一時フォルダ/teikyohyo-fax-tessdata` に置く。

## 精度を測る (開発用)

```bash
node scripts/teikyohyo-fax/eval.mjs <out>/claude.json --gt <gt.json> --snapshot <snapshot.json>
```

★ 正解データ `gt.json` (目で読んだ氏名・番号) は個人情報なので repo に入れない。`--gt` で外から渡す。

## 教訓

- プロンプトの例に **実在の事業所名・人名を書かない** (例に書いた「ケイ・ティ・サービス」に引きずられ、p21 の居宅名を取り違えた)。
- ページごとの API 呼び出しは独立 (会話・履歴を持たない) なので、ほかのページの値は混ざらない。
